# INDIA_CONTEXT.md — making AirPower India-specific (honestly)

Rule of thumb: **real geography, climate and civil infrastructure; fictional military units, bases and order of battle.** This gives realistic, India-relevant behaviour without claiming access to real operational data (see `HONESTY.md`).

## 1. What is real vs fictional

| Element | Treatment |
|---|---|
| India map, terrain, elevation, climate zones | Real (open data) |
| Weather | Real forecasts from open APIs for Indian coordinates; synthetic seasonal weather generator as offline fallback |
| Civil airports / runways (used as alternates and context) | Real, from public open datasets |
| Civil airspace structure | Real where public (open airspace data); otherwise synthetic zones |
| Air force bases, squadrons, units, tail numbers, real aircraft-to-base assignments, real order of battle | **Fictional only.** Use codenames such as `BASE-N1`, `BASE-W2`, `BASE-NE1`. Never real unit or squadron names |
| Threat zones | Abstract circles/polygons with no named adversary and no real deployment claims |
| Aircraft types | Generic (FTR-A, TPT-B, HEL-C, ISR-D, TKR-E), placeholder performance |

## 2. Operating regions (approximate bounding boxes — verify on the map before use)

Place fictional bases inside these boxes; they are for terrain/climate realism, not to mimic real bases.

| Region | Approx. lat | Approx. lon | Realism drivers |
|---|---|---|---|
| North / high-altitude | 30–35 N | 74–79 E | Mountains, high elevation, winter snow and fog, thin air |
| West / desert | 24–29 N | 69–75 E | Heat, dust storms, long distances |
| Central / peninsular | 18–24 N | 75–82 E | Monsoon rain, central hub role |
| East / North-East | 24–28 N | 88–96 E | Heavy rain, low cloud, hills, narrow terrain |
| South / coastal and islands | 8–15 N | 72–80 E (plus island groups) | Cyclones, maritime distances |

## 3. India-specific realism features to implement

1. **Season presets** for the scenario generator: `pre_monsoon_heat_dust` (Apr–Jun), `monsoon` (Jun–Sep), `post_monsoon_cyclone` (Oct–Dec, mainly east/south coasts), `winter_fog_north` (Dec–Feb, north and Indo-Gangetic plain). Each preset changes weather severity, visibility, ceiling and wind distributions. Distribution parameters are config placeholders, not claimed statistics.
2. **Elevation and temperature effects.** Each `Base` gets `elevation_m` (from open elevation data) and a temperature. Compute density altitude with a standard approximation; reduce payload capacity and range accordingly (physics-based, documented, labelled approximate). High-altitude northern bases then genuinely constrain loadouts.
3. **India-relevant mission categories** (all logistics-level): `HADR` (humanitarian assistance and disaster relief, e.g. floods, cyclones, earthquakes), `SEARCH_AND_RESCUE`, `AIRLIFT` to remote/high-altitude locations, `AIR_DEFENCE_PATROL`, `RECONNAISSANCE`, `AERIAL_REFUELLING`. HADR missions carry a `disaster_event` reference and can appear suddenly as `NEW_MISSION` events with high priority, which is a strong retasking demo.
4. **Civil-military airspace sharing.** Model public civil air routes as `CORRIDOR`/`DANGER` zones with time windows; plans must avoid or cross them only in allowed windows.
5. **Alternate airfields.** Real public civil airports as divert options; feasibility checks fuel for divert.
6. **Time and units.** Internal UTC; default UI display IST (UTC+5:30). Display toggle for km/nm, km/h/kt, m/ft.
7. **Weather integration.** `OpenWeatherAdapter` queries real forecasts for each base's coordinates (cached, with offline fallback). If a fictional base is placed at a real-region coordinate, label the weather "real forecast for approximate location".
8. **Seasonal demo scenarios** saved in `scenarios/`: e.g. `monsoon_flood_hadr.json`, `winter_fog_north.json`, `cyclone_east_coast.json`, each generated by seed.

## 4. Candidate open data sources (verify licence/terms before use; record in `DECISIONS.md`)

- Weather: Open-Meteo (forecast); India Meteorological Department public products if terms allow.
- Elevation: SRTM or equivalent open elevation data.
- Airports/runways: OurAirports.
- Airspace: OpenAIP.
- Civil traffic context: OpenSky Network (rate-limited, optional).
- Predictive-maintenance training data: NASA public turbofan degradation dataset (real equipment-wear patterns; still not Indian fleet data, so label accordingly).
- Ask the SIH problem owners/nodal contacts whether a sample data schema can be shared; match structure if they do.

## 5. Sensitivities

- **Map boundaries:** India's external boundaries must be shown as per official Government of India depiction. Do not use a basemap that renders them differently without checking; if the basemap's boundaries are wrong, overlay the correct boundary layer or use a style that supports it. Log the choice in `DECISIONS.md`.
- **No real order of battle or deployments**, no real adversary names, no coordinates of real sensitive installations. Keep bases fictional and zones abstract.
- **No claims of IAF/MoD endorsement or use.** Framing: "prototype using synthetic data and open data, India-context scenarios".

## 6. Generator changes required (extend DATA_MODEL §5)

- `Base`: add `region`, `elevation_m`, `climate_zone`.
- `Scenario`: add `season_preset`, `region_mix`.
- `Mission`: add `category` values `HADR`, `AIRLIFT`; optional `disaster_event`.
- `Weather`: generator reads `season_preset` and base `climate_zone`.
- Add `scenarios/` presets listed in §3.8.

## 7. Presentation talking points (truthful)

- "Real Indian geography and seasonal weather, fictional units and bases."
- "Scenarios reflect India's operating realities: monsoon, high-altitude bases, fog, cyclones, disaster relief."
- "Plugs into real feeds through the adapter layer when access exists."
